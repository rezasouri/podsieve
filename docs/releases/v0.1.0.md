# PodSieve v0.1.0 — Initial Preview

> **Pre-release:** This is an early development preview, not a validated stable release. End-to-end GPU inference and the complete Windows model workflow have not yet been verified as part of release qualification.

PodSieve is a **local-first speaker diarization and vocal separation desktop application** with a Python CLI. It helps turn podcast, interview, and multi-speaker audio into speaker-labeled WAV clips and annotations.

## Highlights

- **Native Qt Quick / QML desktop UI** powered by PySide6, with local-file browsing and YouTube/Castbox source input.
- **Four-stage workflow:** Ingest → Convert → Separate → Diarize. Run steps individually or use the full-pipeline action from the desktop application.
- **Audio processing:** FFmpeg conversion, BS-RoFormer vocal separation through `audio-separator`, and speaker diarization with pyannote.
- **Processed Data manager:** inspect sources, saved stages, output files, storage usage, and audio previews.
- **Source-safe deletion:** guarded confirmation, source-scoped file removal into local trash, metadata updates, and rollback checks.
- **Speaker-focused output:** JSON, RTTM, source manifests, and speaker-grouped WAV segments; optional custom export directory in the desktop UI.
- **Python CLI:** scriptable stage commands for repeatable local workflows.
- **Quality diagnostics:** optional evidence capture, suspicious-region ranking, and review clips.

## Quick start

See the [installation and setup guide](https://github.com/rezasouri/podsieve#requirements) for Ubuntu/Linux and Windows requirements, CUDA notes, FFmpeg, and gated-model access.

```bash
git clone https://github.com/rezasouri/podsieve.git
cd podsieve
uv python install 3.10
uv sync --locked
uv run --locked python ui/main.py
```

For the CLI:

```bash
uv run --locked python run.py --help
```

> You must accept the access terms for the required pyannote models and configure a Hugging Face token before diarization. YouTube ingestion may require Node.js and working browser/cookie settings. Processing large files requires sufficient disk space, RAM, and suitable GPU hardware.

## Validation status

- The repository has passing CI checks for Python syntax, documentation links, core runtime/storage regressions, and headless Qt/QML/bridge regression tests.
- UI tests include local audio ingest/FFmpeg conversion and mocked orchestration for model-heavy stages.
- **Not yet release-validated:** full BS-RoFormer + pyannote GPU inference on an end-to-end sample; Windows GPU/model compatibility; packaged installers and performance benchmarks.

## Known limitations

- This release provides **source code**, not prebuilt Windows/Linux installers.
- The default environment uses a pinned CUDA-enabled PyTorch stack. A complete CPU-only workflow is not validated.
- The pyannote models require separate model access and compliance with upstream licenses.
- Speaker diarization estimates when speakers talk, but **does not transcribe or identify real people**.
- Quality analysis surfaces potential problems and does **not guarantee** correctly labeled segments.
- Cancellation of a running stage is not implemented in the current desktop UI.
- Source deletion moves owned files to local trash; trash restoration is manual.
- The UI cannot reliably detect a different external CLI process concurrently modifying the same dataset.
